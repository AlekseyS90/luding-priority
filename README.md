# LUDING Priority

Премиальный mobile-first каталог для Telegram Mini App. Текущий коммит реализует визуальный MVP, который запускается в браузере: age gate 18+, главная, карусель спецпредложений, каталог с поиском/категориями/фильтром скидки, карточка товара и локально сохраняемая подборка.

> **Статус:** Frontend MVP на изолированных mock-данных. Ни одна операция не имитирует сервер: отправка подборки пока является демонстрацией интерфейса и перед подключением API должна быть заменена на серверную валидацию цены/остатков и Telegram `initData`.

## Архитектурное решение

Интерфейс отделён от данных: `frontend/src/services/catalogMock.ts` — единственный временный источник каталога, явно отмеченный `TODO: BACKEND INTEGRATION`. Компоненты не содержат товарных данных, скидок или остатков. В production этот модуль заменяется API-клиентом FastAPI; расчёт цены, остатки и отправка менеджеру должны выполняться исключительно backend-ом.

## Запуск

```bash
npm install
npm run dev
```

Откройте `http://localhost:5173`. Для production-сборки:

```bash
npm run lint
npm run build
npm run preview
```

## Переменные окружения

Скопируйте `.env.example` в `.env`. Реальные токены и пароли не коммитятся. Публичный frontend не должен получать `BOT_TOKEN`, пароль администратора или строку подключения к БД.

## Следующий этап: серверная интеграция

1. FastAPI + PostgreSQL, миграции и проверка Telegram WebApp `initData`.
2. Модели пользователей, товаров, правил скидок, подборок и обращений.
3. Импорт Excel с предварительной проверкой, дедупликацией по `Код товара`, import log и обработкой изображений.
4. Telegram-бот: возраст, callback и сообщения менеджеру.
5. Защищённая `/admin`, рассылки с rate-limit Telegram и Docker deployment.

Нельзя добавлять онлайн-оплату, доставку, адреса или формулировки дистанционной продажи алкоголя.
